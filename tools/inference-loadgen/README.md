# inference-loadgen

Client-side load generator for the inference attribution integration test
([test plan](../../docs/testing/inference-attribution-litellm-integration-test-plan.md),
[OpenShift install guide](../../docs/testing/inference-attribution-litellm-openshift-install.md)).

It sends deterministic traffic through LiteLLM and reads the engine oracle counters
(`vllm:*` or `sglang:*`) before and after each case. It writes one JSON record per case for the
assertion runner. It does not query Prometheus or OpenCost.

Standard library only, Python 3.11 or later.

## Subcommands

| Command | Purpose | Plan reference |
|---|---|---|
| `calibrate` | Send requests at several prompt sizes and report the engine's prompt-token delta | Section 5.1 |
| `case` | Run one deterministic case and write its record | Sections 5.1 to 5.3 |

## Keys and secrets

Virtual keys are read from environment variables named by `--key-env`. The tool never accepts a
key as an argument and never writes one to the record.

```bash
export LITELLM_KEY_RAG="$(oc get secret litellm-virtual-keys -n opencost2 -o jsonpath='{.data.rag}' | base64 -d)"
```

## Examples

Calibrate the prompt length against the engine:

```bash
python3 loadgen.py calibrate \
  --gateway http://127.0.0.1:4000 --engine http://127.0.0.1:18000 \
  --model gemma-4-31B --key-env LITELLM_KEY_RAG --user alice
```

Non-streaming case (exact-match case G-01 / O-02 style):

```bash
python3 loadgen.py case --case-id O-02-rag \
  --gateway http://127.0.0.1:4000 --engine http://127.0.0.1:18000 \
  --model gemma-4-31B --key-env LITELLM_KEY_RAG --user alice \
  --requests 20 --prompt-tokens 512 --output-tokens 128 \
  --settle 120 --out runs/O-02-rag.json
```

Streaming case (G-02): add `--stream`. The request sets `stream_options.include_usage`.

## What the record contains

| Field | Meaning |
|---|---|
| `t0`, `t1` | Window bounds for the OpenCost query (Section 5.3) |
| `engine_delta_prompt`, `engine_delta_generation` | Oracle `E_in`, `E_out` (Section 5.2), summed across the engine's counter |
| `client_usage_prompt_total`, `client_usage_completion_total` | Usage reported in responses, a cross-check against the engine delta |
| `requests_sent`, `requests_ok` | Request outcome counts |
| `results` | Per-request status, usage, and latency |

Each case's `--settle` value must cover at least two scrape intervals (Section 5.1). The
tool does not wait for scrapes on its own; set `--settle` from the run's scrape interval.

## Limits

- Prompts come from a fixed corpus. Their token count is whatever the engine reports, so
  `engine_delta_prompt` is the authority, not `--prompt-tokens`.
- `min_tokens` and `ignore_eos` are vLLM extensions. Check that the engine honours them
  (Phase 1 setup) before relying on `E_out`.
- Failure cases (G-05 to G-09), cache replay (G-12) and retries (G-13) are not generated by
  this tool. Inject those faults at the engine or gateway, then run `case` around them.
- Tier A (simulator) results cannot stand in for `[B]` cases (plan Section 3.1).
